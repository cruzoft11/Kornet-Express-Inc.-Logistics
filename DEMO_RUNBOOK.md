## 1. CURRENT APPLICATION OVERVIEW

### Architecture and entry points

- **Frontend:** React 18 + TypeScript + Vite; React Router, TanStack Query, Zustand, Tailwind/custom UI, Recharts. The active frontend entry is [`main.tsx`](./kornet-system/src/main.tsx) → [`App.tsx`](./kornet-system/src/App.tsx) → protected [`AppShell.tsx`](./kornet-system/src/components/AppShell.tsx) and [`routes.tsx`](./kornet-system/src/routes.tsx). **CONFIRMED**
- **Backend:** Node.js 22 + Express + TypeScript. [`server/src/index.ts`](./kornet-system/server/src/index.ts) serves `/api`, health at `/api/health`, and the built SPA; [`server/src/routes/index.ts`](./kornet-system/server/src/routes/index.ts) mounts auth, users, company, audit, support, FS, portal, and logistics routes. **CONFIRMED**
- **Operational database:** SQLite through Prisma (`server/prisma/schema.prisma`, `DATABASE_URL`). **Accounting ledger:** a separate SQLite `accounting.db`, accessed through the FS ledger code (Node `node:sqlite`); operational records are bridged into it. **CONFIRMED**
- **Authentication:** internal `/login`; backend login issues access/refresh tokens, stores hashed refresh tokens, rotates refresh tokens, and records last login. Failed username/IP attempts are temporarily blocked after repeated failures in the current server process. The production secrets must be configured; no current production account/password is verified here. **CONFIRMED**
- **Scope/RBAC:** API routes are authenticated and set the company scope to KORNET. Roles include operations/operator, accounting/accountant, manager, admin, superadmin, and viewer in code/route guards; FS additionally checks `canAccessFs`. Some UI visibility and API write guards differ, so do not promise a role matrix without checking the actual account. **CONFIRMED**
- **Main signed-in start page:** `/dashboard`. Public routes outside the ERP shell: `/track`, `/track/:ref`, `/portal/login`, and `/portal`. **CONFIRMED**
- **Navigation actually generated by the active shell:** Dashboard; Operations (Quotes, Ocean Export/Import, Air Export/Import, Domestic/Trucking, P/D Orders, Vehicle Inventory, Fleet & Dispatch, Customer Tracking); Billing (Invoices & Credits, Receivables, Payables, Disbursements, Accounting Bridge); Ledger (FS) (overview, journals, vouchers, chart of accounts, reports, posting, month-end, banks, suppliers, signatories); Directories (customers/vendors, ports, billing codes, tariffs/rates; currencies is a route but hidden); Admin (users, settings, integrations, audit log; UI Kit). Some detail/board routes are hidden from the menu. **CONFIRMED**
- **Legacy/alternate UI:** `LogisticsSidebar` and `LogisticsSystem`/`FSSystem` files remain in source, but the active `App.tsx` routes through `AppShell` and `appRoutes`. Do not use the legacy sidebar as the authoritative current menu. **CONFIRMED**

## 2. CURRENT BUSINESS PROCESS MAP

### Quote to shipment

```text
START: Operations > Quotes
  ↓
Quote list/editor: customer, mode/direction, lane, validity, cargo, charges
  ↓ Save
POST/PATCH /api/quotes + cargo/charge create/update APIs
  ↓
Quote, CargoLine and Charge records stored; quote status is maintained separately
  ↓ Accepted/eligible and not expired/rejected
Convert action → POST /api/quotes/:id/convert
  ↓
Shipment created as BOOKED; quote cargo and charges copied; shipment sequence assigned
  ↓
Shipment workspace → operations, documents, status events, accounting, close checks
```

Conversion rejects rejected/expired or elapsed-validity quotes; an already-converted quote returns its linked shipment. Recent code recalculates copied cargo totals when the new shipment's derived totals are zero. **CONFIRMED**

### Shipment operations and tracking

```text
START: Operations > Ocean/Air/Domestic file list
  ↓
Open file → General / Cargo / Containers / Charges / Documents / Timeline / Accounting / Close
  ↓
Create/update shipment, cargo, container, charge, doc, or status event
  ↓
POST/PATCH /api/shipments, /cargo-lines, /containers, /charges,
/transport-docs, /status-events
  ↓
Shipment and child records updated; cargo edits recalculate shipment totals;
tariff application may create/update charges when a matching tariff exists
  ↓
Status steps in the UI: BOOKED → LOADED → IN_TRANSIT → ARRIVED → CLEARED
→ DELIVERED → CLOSED
  ↓
Status events can include code, location, notes, and public visibility
  ↓
/track/:ref can show only public milestones and limited shipment details
```

The visible steps are confirmed in UI code; particular transition guards and event requirements must be checked against the live record before demonstrating transitions. Closing has a close-check/preflight; a closed shipment is immutable. Reopening is role-restricted and requires a reason. Do not use a close/reopen button in a client demo. **CONFIRMED**

### Transport document to finance and ledger

```text
START: Shipment workspace > Documents
  ↓
Create/edit HOUSE freight document; issue it
  ↓ POST /api/transport-docs/:id/issue
  ↓
For eligible HOUSE BL/HBL/AWB/HAWB documents, code creates eligible
sales-invoice and AP-bill DRAFTS (not posted); Master and domestic DR/waybill
documents do not trigger this automation
  ↓
Billing > Invoices & Credits / Payables
  ↓
Review/edit/post invoices or AP bills; receipts/checks can settle balances
  ↓
Accounting Bridge: trial validation, then final posting if authorized
  ↓
Bridge journal is written to FS ledger; FS Reports / Month-End can show results
```

Issuing a house document is a **write** that can create records in billing; do not issue a new document live. Recent QA says the automatic drafts were tested, but current data was not independently confirmed in the live session. Posting is a separate financial action. **HIGH CONFIDENCE**

### Other operational workflows

- **P/D:** create/update P&D order → assign/dispatch via board and route/resource records → status changes → completed order. Recent code prevents invalid dispatch selections and uses separate route/vehicle/driver resources; full live workflow remains un-certified.
- **Fleet:** maintain driver and vehicle masters → create dispatch route with resources → track route stage/status. No current demo-quality records were independently verified.
- **Vehicle/RoRo:** create vehicle record with VIN and title/customs/inspection fields → update statuses/holds → issue related docs as applicable. Do not assert exact gate statuses without the live sample.
